# dsh-subagent-route

**在任何一个对话里——包括早就开着的——让某个子代理改用别的渠道、别的模型。**

DSH 派子代理时会带上一份“这次用哪个渠道哪个模型”的设定。本来这份设定只有两个来源：你在对话创建时勾选的允许清单，或者你当下正在用的那个模型。聊了半个月的对话两个来源都靠不上，于是子代理只能跟着主对话的模型走。

这个插件补上第三种来源：派活的时候直接点名。

> [English](README.en.md) | 中文

## 什么时候用得上

- 手上这个对话已经聊了很久，想让子代理顺手拿别家的模型干点杂活，不想为这一次新开对话
- 主对话用贵的模型推理，派给子代理的都是整理资料、跑测试这类体力活，想换到便宜渠道
- 想让两个子代理各用一家的模型，比比同一件事谁做得好
- 手上有个渠道刚配好，想拿子代理当小白鼠试它，又不想动主对话的模型

## 安装

1. 打开 设置 → 插件 → 市场，搜索 `dsh-subagent-route`
2. 点安装
3. **完全退出 DSH，再重新打开**

最后一步不能省：插件在启动时组装，只刷新页面不会生效。也可以按包名从 npm 安装。

## 怎么用

装好之后，对话里的智能体会自己看见两个工具：`subagent_route` 用来派活，派的时候点名渠道和模型；`list_routes` 用来查这台机器上到底有哪些渠道和模型。

说清楚用哪家、哪个模型、干什么活。下面这条拿 DSH 自带的 DeepSeek 官方渠道当例子：

```
派一个子代理，用 deepseek-official 的 deepseek-flash，把 docs/ 下所有 md 文件的错别字挑出来
```

`deepseek-flash` 在界面上显示的名字是 DeepSeek-V4.1-Flash。要换别的渠道，就把 `deepseek-official` 和 `deepseek-flash` 换成你机器上的渠道 id 和模型 id——用 DSH 账号登录的话，官方那条的渠道 id 写作 `deepseek-account`。不确定名字怎么写的时候，先让它列一遍：

```
列一下可用的渠道
```

除此以外什么都没变。官方那个 `subagent` 工具一个字节都没动，行为跟没装插件时一样；已有的对话也不会被改写。

## 设置

设置 → 插件 → 已安装 → **子代理指定渠道**：

这一页只有一件事：**允许的渠道**。它把你机器上的渠道和模型一条条列出来，勾上的才能派出去。

- 一条都不勾就是不限制，这台机器上配过的渠道和模型都能用。这是默认状态
- 勾了几条，就只放行这几条，其余的会被拒绝，报错里会写出你放行了哪些
- 以前勾过、现在这个渠道已经不提供了的条目会单独列在「这些已经不在清单里了」下面，仍然可以取消勾选
- 模型列表读不到时，页面会说明原因并给一个重试按钮
- 卡片上有一行摘要：「不限制」或者「只放行 N 条」

改完点「保存」才生效；保存后不用重启，已经派出去了的子代理也不受影响。

不想让它干活的时候，直接把插件停用就行，不用在这一页找开关。

## 常见问题

**换渠道会不会更贵？** 换个渠道意味着前面聊过的内容要重新算一遍钱，缓存用不上。所以这个工具适合“派出去就干活、不带上下文”的活，不适合让子代理接着主对话往下聊。

**为什么不直接在 DSH 设置页勾选允许的模型？** 那样只对新开的对话生效，而且一次要提交一整个清单。这个插件是给“我现在就想换这一次”用的。

**它和设置页里那份「允许的模型」清单是什么关系？** 没关系，各管各的。那份是给新对话预留的路由，这个插件是运行时另开的一扇门，专门给老对话用。

**照它说的名字派活，提示"这个渠道没有这个模型"怎么办？** 直接派。模型清单只是一份目录，不等于许可名单——某些渠道本来就能调用它没列出来的模型。所以向单个模型提问时，插件会直接去问渠道本身：能调就把这个模型显示出来并注明目录里没有，不能调才把渠道拒绝的理由写给你。

**老对话真的能用吗？** 能。派活的时候是由插件把渠道和模型交给 DSH 的子代理服务，不经过对话创建时那份设定。

**卸载会留下什么吗？** 不会。它没有改任何官方文件，卸载后官方的子代理工具原样运行。设置页保存过的勾选会留在 DSH 的设置里，想清掉的话手动删掉那一条即可。

## 隐私与开销

插件本身不联网、不收集任何东西，也不往磁盘写自己的文件。它做的唯一一件事是把渠道和模型名字转交给 DSH 自己的子代理服务。派出去的子代理按你选的那个渠道计费。

## 卸载

设置 → 插件 → 已安装 → `dsh-subagent-route` → 停用或卸载，然后重启 DSH。
