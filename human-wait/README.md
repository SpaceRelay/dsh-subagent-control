# dsh-human-wait

**只在 PTC 模式下起作用：DSH 等你回话的时候（回答问题、确认计划、批准操作），那条 120 秒的限时暂停，不会因为你想得久就超时。**

PTC 模式（让智能体用 `run_code` 写段程序去跑任务）会给整段程序一条 120 秒的限时，中途弹给你的问题、计划审批、权限批准，都算在这条限时里。你多想了三分钟，回来就看到：

```
Error: code run failed (timeout): execution deadline reached (120000ms)
```

问题卡还会被标成「已中断」。装上这个插件，等你回话的那段时间不再算进去；最多等到你设的上限（默认 24 小时），程序自己跑飞了照样到点就被掐断。

> [English](README.en.md) | 中文

## 什么时候用得上

- 用 PTC 模式跑程序，中途要你回答问题或审批，而你想读完再答
- 遇到过「问题卡突然变成已中断」或者上面那条超时

## 它改什么、不改什么

| 情况 | 没装 | 装了 |
| --- | --- | --- |
| 程序里提问，20 秒答完 | 正常 | 正常 |
| 同一个程序，4 分钟后才答 | 120 秒就被中止，问题卡显示已中断 | 继续等，答案照常送达 |
| 一直不答 | 120 秒中止 | 等到最长等待上限（默认 24 小时）才中止 |
| 程序自己死循环 10 分钟 | 120 秒中止 | 120 秒中止，行为不变 |

## 安装

1. 打开 设置 → 插件 → 市场，搜索 `dsh-human-wait`
2. 点安装
3. **完全退出 DSH，再重新打开**

## 设置

设置 → 插件 → 已安装 → **人机等待**：

- **最长等待**（默认 24 小时；选「无限」表示不设上限）
- 快捷按钮：1 小时 / 24 小时 / 无限
- 字段偏离出厂值时会出现「恢复默认」
- 卡片上有一行摘要

改完点「保存」才生效；保存后约 1.5 秒应用到运行中的插件，不用重启。

## 常见问题

**还是超时了？** 看三处：会话头部有 PTC 标记；插件处于启用状态；等待发生的时候插件确实在运行。三者有一个不成立，它就没法替你暂停计时。

**报错变成 `abort` 了？** 正常。插件是自己主动叫停的，所以类型标成 `abort` 而不是 `timeout`，提示文字里照样有 `execution deadline reached`。

## 隐私与开销

它只是在内存里接管了三处「等你回答」的等待，不写文件、不联网，也不改会话内容。卸载并重启后，DSH 原来的行为就回来了。

## 卸载

在插件面板里停用或卸载，然后重启 DSH；宿主原来的方法会恢复。
